# Capability catalog

This directory holds the planner's tool capabilities, intent mappings, tool
families, and prebuilt catalog inputs. Use this page when you need to inspect
the current catalog or add a curated capability.

Run every command below from the **repository root**, the directory containing
`pyproject.toml` and `configs/`.

## Active runtime planner mode

The active runtime planner mode is **catalog only**. `BR_PLANNER_SOURCE` defaults
to `catalog`; a legacy planner mode is not an executable alternative.

The catalog index is assembled from several sources, so its tool count depends
on the checked-out generated files, compatibility settings, and available
NiWrap definitions. Do not copy a fixed tool count into documentation or tests.

## Files and ownership

| Path | Role | How to treat it |
|---|---|---|
| [`capabilities.yaml`](capabilities.yaml) | Curated capability entries | Edit this for a hand-authored source entry; it does not update the default merged snapshot by itself |
| [`capabilities.merged.yaml`](capabilities.merged.yaml) | Prebuilt merged catalog used by default when present | Treat as a derived runtime input; this public checkout does not ship one unified command to rebuild it |
| [`capabilities.generated.yaml`](capabilities.generated.yaml), [`capabilities.python.generated.yaml`](capabilities.python.generated.yaml) | Generated capability inputs | Regenerate through the owning workflow; do not hand-edit for a lasting change |
| [`intents.yaml`](intents.yaml), `tool_families*.yaml`, `tool_*mappings.yaml`, `tool_synonyms.yaml` | Routing, family, alias, and intent metadata | Edit the narrow file that owns the mapping |
| [`../tools_catalog.json`](../tools_catalog.json), [`../tools_catalog_merged.json`](../tools_catalog_merged.json) | Compatibility tool catalogs | Merged into the catalog index unless `BR_PLANNER_INCLUDE_LEGACY=false` |
| [`../schemas/capabilities.schema.json`](../schemas/capabilities.schema.json) | Capability schema | Authoritative field and enum contract |
| [`../schemas/resources.schema.json`](../schemas/resources.schema.json) | Resource-type schema | Generated by the validation workflow |

The runtime assembly logic lives in the
[`catalog_loader.py`](../../src/brain_researcher/services/agent/planner/catalog_loader.py)
loader. Planner data models live in
[`models.py`](../../src/brain_researcher/services/shared/planner/models.py).

## Inspect the current runtime index

Install the package first using the
[root Python setup](../../README.md#install-as-a-python-package), then run:

```bash
python - <<'PY'
from collections import Counter

from brain_researcher.services.agent.planner.catalog_loader import get_capability_index

index = get_capability_index()
runtime_counts = Counter(tool.runtime_kind for tool in index.by_id.values())

print(f"tools: {len(index.by_id)}")
print(f"packages: {len(index.by_package)}")
for runtime_kind, count in sorted(runtime_counts.items()):
    print(f"{runtime_kind}: {count}")
PY
```

This reports the index built in your current environment. It is more useful
than a number recorded when the README was last edited.

## Validate the curated catalog

```bash
python scripts/maintenance/validate_capabilities.py
```

The validator regenerates `configs/schemas/resources.schema.json`, then checks
`capabilities.yaml` against the JSON schema, canonical resource types, and the
Pydantic loader model. Review the Git diff after running it; generated schema
changes should be intentional.

For focused catalog tests:

```bash
python -m pytest -q \
  tests/unit/planner/test_catalog_loader.py \
  tests/unit/planner/test_capabilities_schema.py
```

## Add a curated container capability

1. Add an entry to `capabilities.yaml`. Keep the ID unique and use resource
   types accepted by `configs/schemas/resources.schema.json`.
2. Include the runtime-specific fields. A container entry must explicitly set
   `runtime_kind: container`, an NiWrap `entrypoint`, and `container` details.
3. Run the validator and focused catalog tests.
4. Check the curated source explicitly while developing:

   ```bash
   BR_CAPABILITIES_SOURCE=yaml python - <<'PY'
   from brain_researcher.services.agent.planner.catalog_loader import get_capability_index

   tool_id = "package.tool.run"
   index = get_capability_index()
   assert tool_id in index.by_id, f"not discoverable: {tool_id}"
   print(index.by_id[tool_id])
   PY
   ```

5. Before claiming the tool is available in the **default** runtime, confirm
   that the maintainer catalog build has refreshed `capabilities.merged.yaml`.
   Editing `capabilities.yaml` alone is not enough, and this public checkout
   currently has no single command that rebuilds the merged snapshot.

Minimal shape:

```yaml
- id: package.tool.run
  name: Tool name
  package: package-name
  runtime_kind: container
  entrypoint: package.version.tool.run
  modality: [fmri]
  capabilities: [preprocessing]
  consumes: [volume_4d]
  produces: [volume_4d]
  resources:
    cpu_min: 1
    mem_mb_min: 512
    gpu: false
    time_min_default: 2
  container:
    package_ref: package-name
    runtime: apptainer
  metadata:
    description: Short description of the operation
```

Use the schema rather than this abbreviated example to decide whether an enum
value or optional field is valid. See
[`docs/how-to-add-tool.md`](../../docs/how-to-add-tool.md) for the broader tool
implementation and registration workflow.

## Source-selection settings

- `BR_PLANNER_SOURCE=catalog`: the only active planner runtime mode and the
  default.
- `BR_CAPABILITIES_SOURCE=merged`: use `capabilities.merged.yaml` when present;
  this is the default.
- `BR_CAPABILITIES_SOURCE=yaml`: start from curated `capabilities.yaml` instead
  of the merged snapshot.
- `BR_PLANNER_INCLUDE_LEGACY=false`: omit compatibility entries converted from
  `configs/tools_catalog*.json`.
- `BR_PLANNER_INCLUDE_NIWRAP=false`: omit dynamically discovered NiWrap
  capabilities.

These flags change which sources feed the catalog index. They do not switch the
planner to a separate legacy runtime.
